# OpenPI π0.5 on Jetson AGX Thor

Run `pi05_libero` with FlashRT FP8 or NVFP4 and compare its actions with official
OpenPI on the same checkpoint, observations and denoising noise.

This example uses two cameras, batch 1, ten denoising steps and action horizon 10.
The commands below use 200 warmups and 1,000 measured calls for steady-state
timing. The reference config is OpenPI's
`pi05_libero`, not LeRobot's model implementation.

## 1. Set up the runtime

Check `nvidia-smi` and `cat /etc/nv_tegra_release`. Use JetPack 7.2 / CUDA 13,
MAXN power mode and fixed clocks when comparing latency:

```bash
sudo nvpmodel -m 0
sudo jetson_clocks
```

Choose either route below.

### A. Pull the FlashRT image

On the Thor host:

```bash
export IMAGE=ghcr.io/flashrt-project/flashrt-thor:thor-v0.2.0
mkdir -p models results
docker pull "$IMAGE"
docker run --rm -it --runtime=nvidia --gpus all --network=host --shm-size=8g \
  -v "$PWD/models:/models" -v "$PWD/results:/results" "$IMAGE"
```

Inside the container:

```bash
cd /opt/FlashRT
export MODELS=/models OUT=/results
export REF=/opt/reference
python -c "import torch; assert torch.cuda.is_available(); print(torch.cuda.get_device_name())"
```

The image contains the actual FlashRT source, compiled kernels, input samples
and separate official reference environments. Model weights stay in your mounted
`models` directory. No login is required for the public image.

### B. Clone, install and compile

Use a new checkout and environment. The host must already have CUDA PyTorch and its matching torchvision
for Jetson Thor and the CUDA 13 toolkit installed.

```bash
git clone --branch fix/thor-runtime-and-guides https://github.com/flashrt-project/FlashRT.git
cd FlashRT
python3 -m venv --system-site-packages .venv
source .venv/bin/activate
export PATH=/usr/local/cuda/bin:$PATH
export CUTE_DSL_ARCH=sm_101a
# Optional in China: export PIP_INDEX_URL=https://mirrors.aliyun.com/pypi/simple
python -c "import torch, torchvision; assert torch.cuda.is_available(); assert torch.cuda.get_device_capability() == (11, 0)"
python -m pip install numpy==1.26.4 safetensors==0.8.0 sentencepiece pillow pybind11 ninja \
  nvidia-cutlass-dsl==4.5.1 quack-kernels==0.4.1 huggingface-hub modelscope==1.40.0 modelscope-hub==0.4.2 requests
python -m pip install --no-deps --no-build-isolation -e .
git clone --depth 1 --branch v4.4.2 https://github.com/NVIDIA/cutlass.git third_party/cutlass
cmake -S . -B build -DGPU_ARCH=110 -DCMAKE_CUDA_ARCHITECTURES=OFF \
  -DCMAKE_BUILD_TYPE=Release -DFLASHRT_ENABLE_PI05_THOR=ON
cmake --build build -j2 --target flash_rt_kernels flash_rt_fp4 fmha_fp16_strided flash_rt_pi05_thor
python -c "from flash_rt import flash_rt_kernels, flash_rt_fp4, flash_rt_pi05_thor"
export PYTHONPATH="$PWD"
export LINGBOT_FA4_SRC="$PWD/csrc/attention/flash_attn_4_src"
```

The last import must succeed. The optional Pi0.5 kernel target is Thor-only;
it leaves the shared kernel module and other hardware builds unchanged.

For source installation, install only the OpenPI reference environment:

```bash
bash docker/install-reference.sh "$PWD/.reference" openpi
export REF="$PWD/.reference" MODELS="$PWD/models" OUT="$PWD/results"
mkdir -p "$MODELS" "$OUT"
```

The installer pins the official code and dependencies and patches Transformers
inside the new reference environment. It does not alter the host's primary environment.

## 2. Prepare weights and tokenizer

If you already have the official converted checkpoint, set `PI05` to its directory
and skip the download/conversion. It must contain `model.safetensors`, `config.json`
and `assets/physical-intelligence/libero/norm_stats.json`.

For a new download, use OpenPI's official checkpoint:

```bash
export JAX_CHECKPOINT="$("$REF/openpi-venv/bin/python" -c \
  'from openpi.shared import download; print(download.maybe_download("gs://openpi-assets/checkpoints/pi05_libero"))')"
```

If Google Cloud Storage is unavailable, download the complete `pi05_libero`
folder from the [ModelScope mirror](https://modelscope.cn/models/zebinyang/Jetson-PI-pi05)
and set `JAX_CHECKPOINT` to that folder. It must contain both `params` and `assets`.
Then convert the checkpoint using the official OpenPI converter:

```bash
"$REF/openpi-venv/bin/python" "$REF/openpi/examples/convert_jax_model_to_pytorch.py" \
  --config-name pi05_libero --checkpoint-dir "$JAX_CHECKPOINT" \
  --output-path "$MODELS/pi05-openpi" --precision bfloat16
mkdir -p "$MODELS/pi05-openpi/assets"
cp -a "$JAX_CHECKPOINT/assets/." "$MODELS/pi05-openpi/assets/"
export PI05="$MODELS/pi05-openpi"
```

The tokenizer is already included in Docker. For native setup:

```bash
mkdir -p "$HOME/.cache/openpi/big_vision"
curl -fL --retry 3 \
  https://storage.googleapis.com/big_vision/paligemma_tokenizer.model \
  -o "$HOME/.cache/openpi/big_vision/paligemma_tokenizer.model"
export FLASH_RT_PALIGEMMA_TOKENIZER="$HOME/.cache/openpi/big_vision/paligemma_tokenizer.model"
```

If the official URL is unavailable, use the [ModelScope tokenizer backup](https://modelscope.cn/models/AI-ModelScope/paligemma-3b-mix-448/resolve/master/tokenizer.model). The backup was checked byte-for-byte against OpenPI's tokenizer.

## 3. Run the reference, then FlashRT

Run from the FlashRT directory, using the variables above:

```bash
"$REF/openpi-venv/bin/python" examples/thor/pi05.py --checkpoint "$PI05" \
  --mode reference --warmup 200 --iters 1000 --output "$OUT/pi05-reference.npz"
python examples/thor/pi05.py --checkpoint "$PI05" --mode fp8 \
  --warmup 200 --iters 1000 --reference "$OUT/pi05-reference.npz" --output "$OUT/pi05-fp8.npz"
python examples/thor/pi05.py --checkpoint "$PI05" --mode fp4 \
  --warmup 200 --iters 1000 --reference "$OUT/pi05-reference.npz" --output "$OUT/pi05-fp4.npz"
```

`examples/thor/assets/pi05_libero.npz` ships with both source and Docker. It is
eight real LIBERO observations with two RGB images and robot state per observation;
you do not need to download the full dataset. Calibration uses all eight samples.
The script pins the same random noise for the accuracy comparison and times only
warmed calls. Reports and action arrays are saved under `OUT`.

## 4. Check the result

Both FlashRT commands must exit successfully and report `passed: true`:

- Action shape: `[8, 10, 7]`, all finite.
- Mean action cosine ≥ 0.999; worst observation cosine ≥ 0.995.
- No gripper sign disagreements.
- Expected warmed latency: approximately 38–41 ms FP8 and 20–23 ms NVFP4.

The public image measured 40.71 ms FP8 and 20.33 ms NVFP4 after 200 warmups
and 1,000 measured calls. Increasing NVFP4 warmup to 1,000 gave 20.28 ms
(a 0.26% difference), with no sustained drift across the timing samples.

Read `pi05-fp8.json` and `pi05-fp4.json` for measured latency, p95 and accuracy.
Clocks, power mode and concurrent GPU work affect timing. An accuracy-only failure
returns a nonzero exit status; running without `--reference` explicitly reports
that accuracy was not checked.

## LIBERO-10 rollout result

FlashRT using OpenPI's `pi05_libero` model achieved **94.29% task success**
(4,243/4,500 episodes across nine complete rounds). Each round evaluated all ten
tasks using the same 50 provided initial states per task, with a different seed.

The evaluated rollout protocol used two cameras, five-action replanning, ten
settling steps and a 520-step control limit. Images were rotated 180 degrees and
resized with OpenCV bilinear interpolation. Normalized actions were clipped to
`[-1, 1]` before quantile unnormalization, preserving the historical rollout
setting. The current library default does not apply that clipping; this result
belongs to the documented rollout protocol.

## Using the library

The benchmark's NVFP4 configuration is explicit:

```python
import flash_rt

policy = flash_rt.load_model(
    checkpoint_dir, config="pi05", framework="torch", hardware="thor",
    num_views=2, use_fa4=True, use_fp4=True, use_fp4_decoder=True,
    awq_alpha=0.5, encoder_p1_combiner="epilogue_hw_nod", encoder_down_variant=8,
)
policy.set_prompt(prompt)
policy.calibrate(observations, percentile=99.9)
actions = policy.infer(observations[0])["actions"]
```

`load_model` selects the Thor frontend and loads weights. `set_prompt` prepares
the language prefix and captures graphs. `calibrate` sets quantization scales
from real observations; do it before the control loop. `infer` uploads the current
images, executes the vision/encoder/action-expert kernels and returns decoded
LIBERO actions with shape `(10, 7)`.

For the normal public policy interface, use
`policy.predict(images=[image, wrist_image], prompt=prompt)`. Changing the prompt
requires setup for the new prefix. The example script contains the complete
input-loading, calibration, timing and reference-comparison code.

The optimized full NVFP4 lowering is selected only for Pi0.5 torch on Thor with
`use_fp4_decoder=True`. The existing encoder-only and JAX routes stay separate.
To build this same image yourself, see [Docker](../../docker/README.md#thor).
