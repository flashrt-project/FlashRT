# OpenPI π0.5 on Jetson Thor

Run the OpenPI `pi05_libero` model with FlashRT FP8 and NVFP4, and compare
its actions against a fresh official OpenPI run.

| Configuration | Value |
|---|---|
| Cameras | 2 |
| Batch size | 1 |
| Denoising steps / action horizon | 10 / 10 |
| Action dimensions | 7 |
| Timing | 20 warmups, 100 measured calls |

## Requirements

- Jetson AGX Thor with JetPack installed. Docker validation used L4T R39.2.1 / CUDA 13.2.
- For Docker: Docker and NVIDIA Container Toolkit; your account must be able to run Docker.
- For native installation: Python 3.12 and CUDA PyTorch on Thor.

Check the device before starting:

```bash
cat /etc/nv_tegra_release
nvidia-smi
nvpmodel -q
```

For China pip access, optionally run `export PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple` before installation or weight preparation.

## Option A: Docker

### 1. Pull and check the runtime

```bash
export IMAGE=ghcr.io/flashrt-project/flashrt-thor:thor-v0.1.1
export pi05S="$PWD/models"
export OUT="$PWD/results/pi05"
mkdir -p "$pi05S" "$OUT"
docker pull "$IMAGE"
docker run --rm --runtime=nvidia --gpus all "$IMAGE" doctor
```

Expected: `gpu` is `NVIDIA Thor`, capability is `[11, 0]`, and
`fa4_available` is `true`.

### 2. Download and convert the weights

```bash
docker run --rm --runtime=nvidia --gpus all --network=host --shm-size=8g \
  -e PIP_INDEX_URL -v "$MODELS:/models" "$IMAGE" prepare pi05
```

This downloads OpenPI's JAX checkpoint, verifies checksums, converts it to
BF16 PyTorch and copies the normalization assets. The output is
`$MODELS/pi05-openpi/`, containing `model.safetensors`, `config.json` and `assets/`.
If you already have this official converted checkpoint, put it there and skip
this step. Use OpenPI weights, not LeRobot weights.

### 3. Run accuracy checks and the benchmark

```bash
docker run --rm --runtime=nvidia --gpus all --network=host --shm-size=8g \
  -v "$MODELS:/models" -v "$OUT:/results" "$IMAGE" validate pi05
```

The command runs the official reference, FP8 and FP4 on the same eight
LIBERO observations. It calibrates before timing and saves reports in `$OUT`.
Continue to **Check the results** below.

## Option B: Clone, install and compile

### 1. Install the runtime

Run these commands in a new working directory. If native setup is already
complete, activate its environment, load `runtime.env` and go to step 2.

```bash
git clone --branch docs/thor-release-and-community https://github.com/flashrt-project/FlashRT.git
cd FlashRT/repro/thor
sudo apt-get update
sudo apt-get install -y python3.12-venv python3-dev build-essential cmake ninja-build git git-lfs ffmpeg libglib2.0-0 libgl1

python3.12 -m venv flashrt-venv
source flashrt-venv/bin/activate
python -m pip install 'torch==2.14.0+cu130' 'torchvision==0.29.0+cu130' --index-url https://download.pytorch.org/whl/cu130

export WORK="$PWD/runtime"
bash setup-native.sh
source "$WORK/runtime.env"
export pi05S="$PWD/models"
export OUT="$PWD/results/pi05"
mkdir -p "$pi05S" "$OUT"
```

`setup-native.sh` compiles the tested Thor runtime and installs separate
official reference environments. Keep this shell open for the next steps.

### 2. Prepare the weights

```bash
bash prepare-models.sh pi05
export PI05="$MODELS/pi05-openpi"
```

An existing compatible checkpoint can be reused by setting `PI05` to its directory.

### 3. Run accuracy checks and the benchmark

```bash
bash run-validation.sh pi05
```

## Use FlashRT in Python

The benchmark above uses the same `load_model → set_prompt → calibrate → infer`
sequence as this example. In native mode, run it in the active environment
from `repro/thor`, keeping `PI05` from the preparation step.

For Docker, first enter the prepared image:

```bash
docker run --rm -it --runtime=nvidia --gpus all --shm-size=8g \
  -v "$MODELS:/models" -v "$OUT:/results" "$IMAGE" bash
export PI05=/models/pi05-openpi
```

Then run:

```bash
python - <<'PY'
import os
import numpy as np
import flash_rt

data = np.load("fixtures/libero_obs_2v_n8.npz")
observations = [
    {"image": data[f"img_{i}"],
     "wrist_image": data[f"wrist_{i}"],
     "state": data[f"state_{i}"]}
    for i in range(int(data["n"]))
]

policy = flash_rt.load_model(
    checkpoint=os.environ["PI05"], config="pi05",
    hardware="thor", framework="torch", num_views=2,
    autotune=3, use_fa4=True, use_fp4=True, use_fp4_decoder=True,
)
policy.set_prompt("pick up the black bowl and place it on the plate")
policy.calibrate(observations, percentile=99.9, verbose=False)

result = policy.infer(observations[0])
actions = np.asarray(result["actions"])
assert actions.shape == (10, 7) and np.isfinite(actions).all()
print("Actions shape:", actions.shape)
print("First action:", actions[0])
PY
```

- `load_model` selects the OpenPI π0.5 Thor frontend. `use_fp4=True` enables
  the NVFP4 encoder tier and `use_fp4_decoder=True` enables the NVFP4 decoder.
  Omit both options for FP8.
- Each observation contains two uint8 RGB images (`image`, `wrist_image`) and
  the robot state vector. The example uses the bundled real LIBERO frames;
  replace these fields with your own observations in the checkpoint's convention.
- `set_prompt` prepares the language instruction. `calibrate` uses real
  observations to determine activation scales before the inference loop.
- `infer` returns a dictionary; `actions` is the decoded **10 × 7** action
  chunk. After setup, call `policy.infer(next_observation)` for each new input.
  Set up the prompt again when the instruction changes.

Expected output starts with `Actions shape: (10, 7)`. For numerical comparison
and latency, use the validation command above rather than timing model loading.

## Check the results

Successful validation ends with `combined accuracy status: 0`. Run this
on the host, using the same `$OUT` as above:

```bash
python3 - "$OUT" <<'PY'
import json, sys
from pathlib import Path
out = Path(sys.argv[1])
for tier in ('fp8', 'fp4'):
    accuracy = json.loads((out / f'pi05-{tier}-accuracy.json').read_text())
    timing = json.loads((out / f'pi05-{tier}.json').read_text())
    assert accuracy['passed'], f'{tier}: accuracy failed'
    print(f"{tier}: PASS, cosine={accuracy['mean_sample_cosine']:.6f}, latency={timing['p50_ms']:.2f} ms")
PY
```

Expected results from the public image:

| Tier | Mean cosine | Worst-sample cosine | Latency |
|---|---:|---:|---:|
| FP8 | 0.999900 | 0.999744 | about 40.6 ms |
| FP4 | 0.999691 | 0.999299 | about 20.0 ms |

Passing requires equal, finite action tensors, mean cosine ≥0.999,
worst-sample cosine ≥0.995 and zero gripper-sign disagreement. Latency times
`infer(observation)` through delivered actions with GPU synchronization.
These are fixed-observation numerical checks, not a robot task-success test.
Latency varies with power mode and clocks. [Recorded results](results.md).

If loading fails with missing or unexpected weight keys, prepare the model
again in a fresh model directory using the converter above. If validation
fails, check `$OUT/openpi.log` and `$OUT/pi05-fp8.log` / `pi05-fp4.log`.
