# DM05 attention kernels on RTX SM120

PR #225 adds the opt-in `flash_rt_dm05` module alongside the shared FA2
BF16-to-FP8 output epilogues. The module supplies two attention kernels for
DM05's LIBERO VLA workload:

- `dm05_vit_attn_hd72`: full SigLIP self-attention at head dimension 72, reading
  fused BF16 Q/K/V. It supports an optional static E4M3 output for an FP8
  projection consumer. With that output enabled, the BF16 output is left
  untouched. Sequence length must be a multiple of 128; `D = NH * 72` and
  `D % 8 = 0`. The query tile selector `mt` is 1 or 2.
- `dm05_prefix_attn`: Gemma3 prefix attention with a per-row key limit, so row i
  attends to keys `[0, lim[i])`. That expresses a mask which is causal over text
  and bidirectional inside each image block, in one launch per layer. FA2 cannot
  express it directly (its masks are causal or sliding-window, and `seqused_k` is
  per batch rather than per row), but the same mask is reachable by decomposing
  the prefix into causal and non-causal FA2 calls, which is what the DM05
  pipeline does by default. It selects this kernel only under its
  `prefix_attn_single_call` option, which is off because the decomposition
  measured faster there. This entry is therefore opt-in and not on that
  pipeline's default path.
- `dm05_ae_decode_attn`: grouped-query action-expert attention at head dimension
  256, including single-pass and split-KV execution. `R = G * T` must be an
  instantiated row count; query support through `dm05_ae_decode_attn_supports_r`.
  Allocate split workspaces with the published size helpers and initialize the
  `NKV` int32 counters to zero before first use. The combine path resets them
  for subsequent calls and CUDA Graph replay.

The module also supplies the action expert's weight-only int8 GEMM (W8A16),
which is on that pipeline's default path:

- `dm05_w8a16_pack` repacks an `(N, K)` int8 weight into the fragment order the
  GEMMs read; `N` must be a multiple of 16 and `K` of 32.
- `dm05_w8a16_tc` computes `out[m, n] = bf16(sum_k x[m, k] * dequant(w[n, k]))`
  for `M <= 16`, bf16 activations and fp32 accumulate on bf16 tensor cores.
  int8 to bf16 is exact for `|q| <= 127`, so the tensor-core product equals the
  scalar int8 x bf16 product and the per-channel scale is applied once after the
  K reduction.
- `dm05_w8a16_tc3` is the same GEMM over a weight whose `N` concatenates three
  segments, each written to its own buffer with its own leading dimension, so a
  fused q|k|v GEMM can put k and v straight into cache rows.
- `dm05_w8a16_tc_glu` applies the gated MLP epilogue over a fused `[gate | up]`
  weight, reproducing the separate gate GEMM, up GEMM and multiply roundings.

This family is W8A16 (weight-only). FlashRT's other int8 path is W8A8 and is not
built for `GPU_ARCH=120`, so it is not a substitute.

The module is disabled by default through `FLASHRT_ENABLE_DM05=OFF`. Enabling
it requires `GPU_ARCH=120`. It has a separate target and shared library, and
is not referenced by the default shared-kernel target. Its raw-pointer API
requires caller-owned device buffers, workspace and a CUDA stream. The exact
layouts are documented in `csrc/kernels/dm05/*.cuh` and the pybind docstrings.

## Build and test

From the FlashRT repository root, with CUDA and CUTLASS available:

```bash
cmake -S . -B build-dm05 -G Ninja \
  -DCUTLASS_DIR=/path/to/cutlass \
  -DGPU_ARCH=120 -DFA2_ARCH_NATIVE_ONLY=ON \
  -DFA2_HDIMS=256 -DFA2_DTYPES=bf16 \
  -DFLASHRT_ENABLE_DM05=ON
cmake --build build-dm05 \
  --target flash_rt_dm05 flash_rt_fa2 flash_rt_kernels -j4
PYTHONPATH=. python -m pytest \
  tests/test_dm05_smoke.py tests/test_fa2_fp8_output_epilogue.py -q -rs
```

`test_dm05_smoke.py` checks both kernels against FP64 attention references,
query-tile agreement, split-KV agreement, counter reuse, FP8 quantization byte
identity and rejection of unsupported shapes. An unbuilt module skips these
checks; skipped tests do not validate the kernels. These operator tests do not
establish complete DM05 model quality or deployment performance.

The FP16-only FA2 import regression is independent of DM05's BF16 inputs:
configure `FA2_DTYPES=fp16`, build `flash_rt_fa2`, then check both new FP8-output
bindings import and report "not compiled" before any CUDA launch. Native mode
also exports these two entry points through `fa2_native_exports.map`.

## Verification record

Audit follow-up on RTX 5090 (SM120), CUDA compiler 13.0, GCC 13.3,
PyTorch 2.11.0+cu128 / CUDA runtime 12.8:

- FP16-only, head dimension 256, native FA2 + Python adapter: actual compile,
  link, exact raw export inventory, adapter import and both unavailable
  BF16-to-FP8 entries raising before launch; **10 passed**.
- BF16, head dimension 256, DM05 enabled, native FA2 + Python adapter:
  `flash_rt_fa2`, `flash_rt_kernels` and `flash_rt_dm05` all compiled and linked.
  Combined FA2 build checks, FA2 output-epilogue numerical tests and DM05
  numerical tests: **46 passed, 1 skipped**. The FP16-only rejection test is deliberately
  skipped in this BF16 configuration.
- Complete DM05 model/checkpoint quality and end-to-end deployment performance
  were not rerun in this follow-up.

Both builds used `FA2_ARCH_NATIVE_ONLY=ON` and `FA2_HDIMS=256`. The BF16 build
used `FLASHRT_ENABLE_DM05=ON` and `FLASHRT_ENABLE_QWEN3_FP8_PREFILL=OFF`.
